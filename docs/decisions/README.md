# Журнал архитектурных решений (ADR)

Здесь фиксируются **ключевые, трудно-обратимые решения** по detox-parser: те,
что меняют контракт, вводят зависимость, задают границу подсистемы или
сознательно отклоняют очевидную альтернативу. Мелкие решения уровня кода сюда
не пишем — для них достаточно комментариев и истории git.

## Зачем

Чтобы через полгода (или новый человек) видел **не только что выбрано, но и
почему**, какие были альтернативы и при каких условиях решение стоит
пересматривать. Код отвечает на «как», ADR — на «почему именно так».

## Формат

Один файл = одно решение. Имя: `NNNN-краткий-слаг.md` (номер сквозной,
четырёхзначный). Шаблон — `_template.md`.

Статусы:

- **Proposed** — спроектировано, обсуждается, ещё не реализовано.
- **Accepted** — принято и (частично) реализовано.
- **Superseded by NNNN** — заменено более новым решением (ссылка обязательна).
- **Deprecated** — больше не актуально, но оставлено для истории.

Решения **не удаляем и не переписываем задним числом** — если передумали,
заводим новый ADR со статусом, который заменяет старый. История решений так же
ценна, как сами решения.
